MCP 在大模型工具调用中扮演关键角色，但它与其他通信协议有本质区别。

## MCP 与 RPC（远程过程调用）

RPC 的设计初衷是让程序像调用本地函数一样调用远程服务，核心在于**过程的同步执行**和**命令式控制**。它要求调用方和被调用方之间有严格预定义的接口、函数签名和数据类型，通信语义聚焦于"如何执行"。

MCP 则服务于具有推理能力的大模型，核心在于提供**结构化的上下文**和**工具使用指引**，实现从"执行"到"决策"的转变。

| 维度 | RPC | MCP |
|------|-----|-----|
| 定位 | 执行引擎 | 上下文与能力抽象 |
| 驱动方式 | 命令式，明确指定执行什么 | 意图驱动，由模型决策 |
| 交互模式 | "执行这个函数" | "提供这些工具，让 AI 决定如何使用" |
| 接口定义 | 严格预定义的函数签名 | 结构化的工具描述 |

**关键区别：** MCP 虽然在消息结构上采用 JSON-RPC 格式，但并不建立在传统 RPC 架构之上。MCP 的通信基于 STDIO 或 HTTP（SSE、Streamable HTTP），JSON-RPC 仅作为消息封装使用，而非远程过程调用语义。Dubbo、gRPC 等 RPC 框架不是 MCP 的技术基础。

## MCP 与 A2A（智能体通信协议）

A2A（Agent-to-Agent Protocol）由 Google 等厂商推动，专门解决多智能体系统中的**智能体协作**问题。

**MCP 解决单个智能体如何使用工具，A2A 解决多个智能体如何协同工作。**

### 定位差异

**MCP：垂直集成与赋能**

专注于将智能体与外部资源（数据库、企业 API、第三方工具）进行标准化连接，是智能体获取工具能力的桥梁。

**A2A：水平协作与编排**

专注于智能体之间的发现、协商、任务传递、成果交换和任务生命周期管理，让不同专业智能体能够像团队成员一样协作。

### 协作示例

以旅行规划系统为例：

1. 用户需求："帮我规划本周末去南京旅游两天的行程"
2. **A2A** 协调"行程编排代理"、"机票预订代理"、"酒店查询代理"等多个智能体
3. "机票预订代理"执行子任务时，通过 **MCP** 调用"航班工具"查询航班信息
4. 各代理通过 **MCP** 完成工具操作后，通过 **A2A** 将成果反馈给"行程编排代理"汇总

### 关系总结

| 协议 | 解决的问题 | 作用范围 |
|------|-----------|---------|
| MCP | 智能体获取外部工具能力 | 智能体 ↔ 工具/数据 |
| A2A | 智能体之间对话与协作 | 智能体 ↔ 智能体 |

两者互补：**A2A 提供智能体之间的对话协调规范，MCP 提供智能体获取外部世界工具能力的规范**。结合使用可构建既具备强大工具调用能力，又具备高效复杂任务处理能力的多智能体应用架构。
